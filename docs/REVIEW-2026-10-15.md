## Verdict

The game engine is in good shape. The cascade logic, card conservation and bot play survived 1,000+ fuzzed games without a single lost or duplicated card. The serious problems were at the edges:

1. **Phones never got updates.** The service worker served the app shell cache-first, and nothing changed `sw.js` between deploys. Installed PWAs kept running whatever build they first cached. That is the root cause of the "fixed weeks ago, still reported broken" problem in CLAUDE.md, which blamed it on undeployed commits. **Fixed:** the server stamps a build id into `sw.js`, and the shell is now network-first.
2. **Turn notifications have never delivered.** pywebpush cannot parse the PEM key the server stored, so every send failed into a log warning. **Fixed.**
3. **The Hall of Fame never recorded a game.** The README says wins record automatically, but nothing did: the web "Record Winner" button said "coming soon", and the iOS one sat on a screen that never shows. **Fixed:** recording is now automatic and idempotent.
4. **One double-tap could replay or wipe a Tribal Council.** It could also strand the Final Tribal on iOS (about 1 in 3 single-human games). **Fixed**, and the fix works with the iOS builds already installed.
5. **Every phone received the draw pile in order,** including where each Tribal Council card sits. **Fixed:** the pile is sent face down.
6. **Security holes:**
   - Stored XSS through Hall of Fame names.
   - A brute-forceable Discord link-code claim.
   - Spoofable client-IP headers that defeated the island-code throttle.
   - A push-endpoint SSRF.

   **All fixed.**

## What changed

### Tribal Council integrity (server + engine)
| Was | Now |
|---|---|
| A second `complete_tribal` call during Final Tribal replayed every vote-out. It restarted Final Tribal and wiped the jury, or flipped a finalist's last card and crowned the other with no jury | Only a revealed council closes, and only once |
| A second "It Is Time to Vote" emptied a ballot box whose Vote Cards were already spent | Repeating it in voting is a harmless no-op; it's refused after voting |
| Re-advancing to the current phase cleared `hasVoted`, or `immunityPlayed` (allowing a second idol) | A same-phase advance is a no-op |
| Advancing to `reveal` skipped the tally and wedged the council | `reveal` always goes through `reveal_votes` |
| An idol could be played before the vote, or after the tally (consumed for nothing) | Only in the idol window |
| One silent Idol Nullifier holder froze a bot-led council forever | 45s deadline, swept on read and on the heartbeat; bot Leaders also call time |
| A Control The Vote waiting on Sorry For You let the vote go ahead without it. If the council ended first, the thief took the victim's **next** council's Vote Card | Voting waits on the raid window; a held take dies with its council |
| Reset Tribal destroyed spent Vote Cards and wedged the drawer's turn, since neither client has an end-turn button | Refused once ballots exist; before that it discards the card and passes the torch |
| Final Tribal controls went to the last council's Leader on iOS, so a tie could never be broken | Every leader signal names the Final Tribal Leader |

### Ballots, cards and rules fidelity
- **Vote counts:** each entry must be a whole number ≥ 0. Before, `[{B: 5}, {C: -4}]` spent one Vote Card for five votes.
- **Tribal Council cards are shuffled.** Singles always came before doubles, so every game ran the same elimination schedule.
- **Camp Raid survives a council.** The card takes "the next card they draw", but a Tribal in between erased it. The wrong legacy steal-time Camp Raid mechanic is removed.
- **"Unclear who is voted out" ladder:** tiers that fit inside the picks owed are now forced. The Leader could previously spare the one non-immune player the ladder says goes first.
- **Refused with the card kept in hand:**
  - self-targets (Goodwill on yourself minted a second ballot);
  - an eliminated alliance partner or victim;
  - a Spy Shack aimed at a Vote Card;
  - Control The Vote played through `play_card` without its checks (the web's path);
  - unknown advantage types.
- **Discard Pile and protection:** played idols and nullifiers reach the Discard Pile. A fresh idol protects a player whose earlier idol was nullified.
- **Penalties:** a Sorry For You penalty never discards a given Goodwill Gamble, which is a mandatory ballot.

### Systems and security (server)
- **Service worker:** `/sw.js` is served with the build hash stamped in and `Cache-Control: no-cache`. The shell is revalidated. `/api/ping` reports the build, so deploys can be verified.
- **Web Push:** keys are signed via `Vapid02.from_pem`. Endpoints must be a real push service: https on FCM, Apple, Mozilla or WNS. Subscriptions are size-capped, pruned with their games, and written atomically.
- **Draw pile:** sent face down as same-length placeholders plus `deckCount`, so installed iOS builds keep their count.
- **Hall of Fame:**
  - automatic and idempotent;
  - accepts only a finished game's real winner;
  - an unreadable `winners.json` is preserved, never overwritten;
  - names use a safe charset (they were rendered into an HTML attribute).
- **Throttles:**
  - Client-IP headers are trusted only from loopback, which is where cloudflared connects from.
  - Throttle maps evict old entries instead of clearing everyone.
  - Wrong Discord link claims are budgeted per IP and globally, not per caller-chosen Discord id. That id could be rotated to sweep all 21,600 codes in seconds.
- **Removed:** `global_reset` (sent to every socket on the server) and `/api/batch` (unused, and it skipped every guard).
- **Request handling:**
  - Ids must be strings. A list where an id belonged half-applied an action, then saved it.
  - 500s log tracebacks and no longer echo internals to clients.
  - The Story So Far line is appended **before** the broadcast; other phones ran one action behind.
- **Bots:** bot moves are narrated. Before, a bot-led council announced no elimination at all.
- **Game lifecycle:**
  - `reset_game` clears the last game's discard pile, open windows and the bots' ledger.
  - GC runs on the event loop and survives errors. It was a real OS thread that a "dict changed size" error could kill for the life of the process.
- **Saving and loading:**
  - One unhealable game no longer takes down the whole store on load.
  - Saves are compact and fsynced: about 4× faster, and durable across a power cut. **`games.json` is no longer pretty-printed;** read it with `python3 -m json.tool games.json`.
- **Smaller fixes:**
  - Game ids are checked for collisions.
  - Expired windows are resolved on the heartbeat for every game.
  - The pace setting works under a bot Leader.
  - `HOST` env support.
  - A broken gevent install fails loudly.
  - `POST /api/access/forget` clears the HttpOnly access cookie.
- **Dependencies:** Flask 3.1. `pip-audit` flagged 2.3.3; the full suite and a live websocket smoke test pass on both versions. The gevent floor is now 23.9.0 (CVE-2023-41419). The unused `python-dotenv` is dropped.

### Computer players (`bots.py`)
- **Idol Nullifier window:** a bot Leader calls time on a silent human's window. One that holds a nullifier itself no longer closes the window for everyone on its first tick.
- **Tie-breaks:** a bot Leader never breaks a tie on itself. It used to in 60 of 200 games.
- **Rocks Challenges:** the starter clears a finished Challenge after the reveal, so a bot's turn no longer waits on a human's Continue.
- **Spy Shack:** bots only name a card they can actually take.
- **Failures and broadcasts:** crashes count as refusal strikes, and only successful actions broadcast.
- **Heartbeat:** it skips lobby and finished games and forgets deleted ones.

### Discord bot (`discord_bot.py`)
- **Game selection:**
  - It re-checks which game to mirror while watching. Before, it stuck to the first game it found, sorted by **game id**, so last night's abandoned table kept tonight's channels.
  - It switches after two consistent checks, and releases a game that leaves the list.
- **Startup and shutdown:**
  - Login is lazy, so a down island no longer crashes startup.
  - A config error re-checks every minute instead of looping launchd restarts, which risked Discord's identify limit.
  - SIGTERM unlocks channels before exiting.
- **Errors:**
  - Retries back off from 5s to 5 min, with one traceback per kind of failure.
  - `/link` no longer shows players raw transport errors.
- **Moderation:** cleanups only lift bars and mutes the bot can attribute to Survivor players. Players who left voice are fetched, so their bars actually lift.

### iOS app — **uncompiled**
- **Final Tribal:** `leader`, `jury` and `questions` decode leniently. The leader bar and tie-break follow the Final Tribal Leader, and the questions are shown.
- **Resets:** `game_reset` is filtered by gameId, `global_reset` is ignored, and a reset re-syncs instead of faking a lobby.
- **Robbery banners:** tapping the first banner no longer dismisses the next one.
- **Joining and leaving:**
  - A failed join after Create no longer strands you in a lobby you can't leave.
  - Names follow the server's 2–30 character rule.
  - A deleted game (404) sends the phone home.
  - Leaving mid-game asks first.
- **Decoding:** `winner` decodes as either an id or a `{playerId}` record.
- **Accessibility:**
  - Overlays are modal for VoiceOver.
  - Tied vote counts sort the same on every phone.
  - The split-ballot and remove-bot buttons are 44pt.

- **`redeploy.sh`:**

  - snapshots runtime state (last 20 kept);

## Deploying this

1. **Server and web: `bash deploy/redeploy.sh`** on the Mac, after merging. It will:
   - upgrade Flask to 3.1 during the pip step;
   - snapshot runtime state to `~/srv/survivor-backups/`;
   - confirm `/api/ping` answers.
2. **The first update after this deploy.** A phone still on the *old* service worker fetches the new one on its next navigation. Because the old worker is cache-first, some phones need one extra reload, or a close and reopen of the home-screen app. From then on, updates arrive by themselves.
3. **iOS needs a TestFlight build,** and it must be **built in Xcode first**: these changes were written without a compiler. The server-side Final Tribal fix already protects the builds on phones today.
4. **Edit by hand:** set `ThrottleInterval` to 60 in the *installed* `~/Library/LaunchAgents/com.survivor-game.discord-bot.plist`. Redeploy never touches that copy because it holds secrets.

## Not fixed — recommendations, in priority order

1. **Identity and hidden information.**
   - A player is whoever claims their `playerId`.
   - Every phone receives every hand and the in-progress ballots (`currentVote.votes`).
   - Fix: mint a per-player token at join, require it in `handle()`, and send each phone a state with other hands redacted.

   This is the largest remaining fairness and security gap. It is a coordinated server, web and iOS change.
2. **Final Tribal liveness.**
   - Jury voting has no deadline, so one absent juror stalls the end of the game.
   - `change_leader` never updates `finalTribal.leader`.
   - Only the Final Leader's phone can advance.

   Add a deadline, or let any finalist advance after a timeout.
3. **A data directory and backups.**
   - Add `SURVIVOR_DATA_DIR`, so runtime state stops living beside the code under `rsync --delete`.
   - Add a nightly backup LaunchAgent.
4. **Logging.**
   - Plists log to `/tmp`, which is unrotated and wiped on reboot.
   - The Socket.IO access log floods the `.err` file.
   - Fix: move logs to `~/Library/Logs/SurvivorGame/` with rotation, turn the access log off by default, and set `HOST=127.0.0.1` in the production plist if nobody plays on the LAN.
5. **iOS follow-ups.**
   - Refresh the card catalog from `/api/cards`. It is bundle-only, so a new card shows as unplayable until the next TestFlight build.
   - Add `scenePhase` resync on foreground.
   - Support Dynamic Type for `Torch.Font.body` and `.label`.
   - Address card plays by uid, not by index.
   - Add re-entrancy guards on view-model actions.
   - Regenerate the stale test fixtures, and add Final Tribal fixtures.
6. **Bot strategy gaps.** Bots never play Control The Vote, I'm The Leader Now, Steal A Vote or Block A Vote, and never cast Extra Votes. They hoard them all game.
7. **Rocks Challenge cap.** A Challenge at exactly `MAX_CHALLENGE_ACTIONS` refuses everything, and no reset path exists. The load heal uses `>`, and a test pins it as intentional. It is only reachable by griefing.
8. **Dependencies.**
   - Split `requirements.txt` into server, bot and dev.
   - Add a lockfile.
   - Consider dropping `gevent-websocket`: it is unmaintained, and the reviewer verified websockets work without it on Flask 3.1.
9. **Repo hygiene. The GitHub repo is public.** It contains:
   - the publisher's rulebook PDFs (about 8 MB, an IP risk);
   - Discord guild and channel IDs in `docs/voice`;
   - a tracked `xcuserdata` directory;
   - about 11 MB of generated screenshots;
   - `companion/`, which is dead code (unreferenced and never served).

   Consider making the repo private, or removing these.
