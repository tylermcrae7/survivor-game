## VERDICT IN ONE PARAGRAPH

The engine implements most of the official game faithfully: correct tribal-council deck table by player count, bottom-card tribal placement, leader = drawer, advantage/discussion/voting/immunity/reveal phase flow, leader tie-break, jury, final tribal with jury vote and leader tie-break, all 17 official card effects plus reactive Sorry For You. **But three core rules are missing or broken**, the biggest being that the 2-lives Survivor Character Card system does not function — one vote-out eliminates you permanently. The web client also has two transport bugs (state resync 405, heartbeat crash) and a redirect bug that makes the app appear completely broken on non-LAN hostnames.

## FINDINGS

### P0 — Breaks the official game

**F1. Character Card lives are not implemented (2 lives → actually 1).**
`characterCards` is set to 2 at join and reset to 2 on game reset — **no code path ever decrements it.** `complete_tribal()` sets `isEliminated=true` on the first vote-out. Official rules: a vote-out flips ONE of your two Survivor Character Cards; you are only eliminated when BOTH are flipped. Consequence: games are roughly half their intended length, and the "voted out once but still fighting" dynamic — the heart of the mid-game — doesn't exist. Verified live: E2E check `bob_lost_character_card` FAILED (still 2 after elimination; player fully removed instead).

**F2. Vote-card economy is absent.**
Official setup: each player gets exactly 1 Vote Card; extras removed from the game; deal 3 action cards; after each tribal, return 1 Vote Card to each surviving player. Actual: `start_full_game()` deals **5 random cards from a deck that still contains all 6 Vote Cards**. Live E2E: initial hands had 0, 1, and 2 vote cards. Voting itself (`cast_vote`) never consumes a card from hand — votes are tracked as flags (`hasVoted`, `extraVotes`). The game is *playable* this way, but hand composition, Knowledge-is-Power targets, steal odds, and Control-the-Vote (which per rules steals a physical Vote Card) all deviate from the official design.

**F3. Client state resync is broken — every sync attempt 405s.**
`state-manager.js:436` calls `apiCall('/game/${gameId}/state')` whose default method is **POST**; the server route only accepts **GET**. Every resync throws "internal server error" toasts (reproduced in the live UI session; server log full of 405 tracebacks). This is the exact path that heals a phone that dropped connection mid-game — your core remote-play scenario.

### P1 — Should fix before game night

**F4. HTTPS-redirect wedge on non-private hostnames.**
Inline script in `index-optimized.html` force-redirects to `https://` unless the hostname is localhost/192.168.x/10.x. The server doesn't speak TLS, so loading via Tailscale IP (100.x), `*.local`, or any public IP = instant redirect to a dead TLS port. This is why the app "hung" the review browser and why the DOM died at the `<head>`. Works fine through the Cloudflare tunnel (real HTTPS) — but anyone hitting the box directly gets a black screen with zero error.

**F5. Steal-before-draw is not enforced server-side.**
Official turn = Steal (mandatory) → Play (optional) → Draw. `draw_card()` checks turn ownership but never `hasStolen`. Verified live in the UI: pressed **Draw Card** first thing on turn 1 — "Card drawn successfully!" The rules engine even computes the phase correctly (`get_current_turn_phase`) — the draw endpoint just never consults it.

**F6. Socket.IO heartbeat handler crashes on every beat.**
`on_heartbeat()` takes 0 args but the client emits `('heartbeat', {t}, ack)` → `TypeError` in the server log every 25s per client. The heartbeat exists specifically to keep websockets alive through Cloudflare — so the keepalive for your chosen hosting path is dead.

**F7. Seven non-official cards are in the deck.**
`survivor_cards.json` claims "Official Survivor Board Game PDF" but contains **74** cards where the official box has **67**: Idol Nullifier ×2, Steal A Vote ×2, Block A Vote ×2, Grant Immunity ×1 appear nowhere in the official Survival Guide (official counts sum to exactly 67 without them). They're implemented and balanced-looking — likely deliberate homebrew from the show — but the docs claim official parity. **Decision needed: keep as a "house deck" option (make it a toggle) or remove for official mode.** Note: the 2025 Rocks expansion guide references combining with "the deck of 76 Action Cards," so the newer base-game printing may have more cards — worth checking a current physical copy before deleting anything.

**F8. Test suite drifted from both the rules and the engine.**
13 suites fail. Sampled failures are test bugs, not engine bugs: `test_deck_composition` expects 3-single/2-double at 5 players — the official table (and the engine) say 2/3; `test_tribal_council` asserts on `game["currentVote"]` key layouts that the server has since changed. The engine's actual tribal table matched the official rules in my live E2E (4 single / 0 double at 3 players, bottom card tribal ✓). The suite needs to be re-pointed at the rules, then kept green — right now it can't catch regressions.

### P2 — Polish / fidelity

- **F9. Tie-break edge rules partial.** Leader tie-break works (verified live: 3-player vote produced a tie, leader broke it). But the official double-elimination cascade (most-votes out first, then leader picks among second-place tie) and the "unclear who is voted out" priority ladder (voted > no-votes > idol-players) aren't modeled — leader gets a free choice among tied players.
- **F10. Final Tribal question wording** differs slightly from the official three questions. Cosmetic.
- **F11. Eliminated players and challenges:** official Rocks rules let eliminated players keep playing challenges; base-game official rules keep jury members present. Current engine bars eliminated players from everything except jury voting — fine for base game, relevant when the expansion lands.
- **F12. Housekeeping:** `games.json` is 2.9 MB with 6 stray numbered copies (`games 2.json`…`games 7.json`) committed to the repo; `ios/SourcePackages/` untracked; git repo corruption (packfile truncated) still outstanding.

### What checked out ✓ (no action)

Tribal deck table per player count · 1 tribal card on deck bottom, rest evenly spaced · tribal triggers immediately on draw, card not added to hand · drawer becomes Council Leader · phase sequence announcement→advantage→discussion→voting→immunity→reveal · advantage cards locked after voting starts · immunity idol negates votes (self or other) · idol timing (after votes, before tally) · Sorry For You reactive interrupt with discard penalty · Camp Raid delayed steal on next draw · Inheritance transfers hand on elimination · all 3 Reward Challenges (RPS, fingers, unique-lowest) · jury accumulation · auto final-tribal at 2 remaining · most-recent-eliminee is Final Leader · jury vote + leader tie-break · duplicate-name/empty-name validation · reconnect endpoint · state persistence with corruption backup.

## EXPANSION: Survivor — Let's Go To Rocks (Exploding Kittens, 2025)

$19.99 · 2-6 players · standalone OR combines with The Tribe Has Spoken. Official rules + Challenge Guide PDFs downloaded to `docs/expansion/`.

**Standalone mode** (not our target, but context): 5 challenge mini-games; win a challenge → wear the Immunity Idol Necklace → you personally pick who flips a character card. Same 2-lives elimination.

**Combined mode — this is the digital opportunity:**
- Add the **5 Orange Challenge Cards** to the action deck. Drawn like action cards, played on your turn.
- Playing one starts a **Challenge** among all non-eliminated players.
- Challenge winner takes the **Immunity Idol Necklace**: immune to votes at the *next* Tribal Council, necklace returns to the table after it.
- If someone already wears the necklace: winner instead draws **3 random non-Tribal-Council cards from the draw pile**.

**The 5 challenges, ranked by digital feasibility:**

| Challenge | Mechanic | Digital fit |
|---|---|---|
| **Highest Bidder** | Bid how many rocks you can pull without hitting the purple one; bid/pass auction, then pull | **Easy** — pure bid + RNG draw; great async UI |
| **1 Now or 2 Later** | Pass the bag; pull 1 or pass (but then must pull 2 next time); purple rock knocks you out | **Easy** — turn-based choice + RNG |
| **Lowest Score Loses** | Secretly pull 0-N rocks from a shared bag; grey +1, purple −2; lowest total knocked out each round | **Easy** — simultaneous secret picks, like existing Power Pair |
| **Pull or Steal** | Pull a hidden rock or steal from a lower-numbered player; purple rock wins | **Medium** — hidden info + steal targeting; engine already does both |
| **Hide 'n' Seek** | Physically palm rocks and bluff-pass around the table while an Observer watches | **Hard** — physical sleight-of-hand; needs a redesign (e.g. timed decoy animations) or exclusion |

Recommendation: implement the deck/necklace framework + the 3 easy challenges first; Pull or Steal second; ship Hide 'n' Seek only if a fun digital analog emerges. All five reuse existing engine patterns (simultaneous secret input = Power Pair; sequential pull-or-pass = new but trivial state machine).

## CORRECTION PLAN

**Phase 1 — Correctness (P0):**
1. Implement character-card lives: vote-out decrements `characterCards`; eliminate only at 0; jury membership only on true elimination. Touches `complete_tribal`, tie-break paths, client player display (show 2 flame/torch icons per player).
2. Vote-card economy: setup deals 3 action + exactly 1 Vote Card (extras out of deck); `cast_vote` consumes vote cards from hand; post-tribal returns 1 Vote Card per surviving player; Extra Vote/Control the Vote move real cards.
3. Fix state sync: make the client call GET (one-line in `state-manager.js`) — or accept POST server-side. Then verify rejoin-mid-game end-to-end.

**Phase 2 — Robustness (P1):**
4. Fix HTTPS redirect (only redirect when the host actually serves TLS; simplest: drop the inline redirect entirely once the permanent Cloudflare tunnel exists, since that URL is already HTTPS).
5. Enforce steal-before-draw in `draw_card()` via the rules engine's phase check (house-rule toggle optional).
6. Fix `on_heartbeat(data=None)` + ack.
7. Decide official-vs-house deck (F7); implement as a game-creation toggle either way; correct the metadata/docs.
8. Repair the test suite against the official rules table + current state shapes; add the E2E API test (from this review) to `tests/e2e/`; run in CI-style via `run_all_tests.py` with the venv.

**Phase 3 — Fidelity (P2):** double-elim tie cascade + unclear-vote priority ladder · official final-tribal wording · repo housekeeping (`games N.json` removal, gitignore `SourcePackages/`, fix corrupt git via fresh clone).

**Phase 4 — Expansion:** necklace + orange-card framework, then challenges in feasibility order (above).

**Sequencing note:** Phase 1-2 items are all small, isolated diffs — the architecture (rules engine separation) makes them cheap. The lives system (F1) is the only one that ripples into the client UI meaningfully. Suggest landing Phases 1-2 + repo repair before the Mac-mini/tunnel deployment we scoped earlier, so game night #1 runs the corrected rules.
