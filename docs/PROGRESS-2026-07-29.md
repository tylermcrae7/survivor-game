## API contract notes for the iOS client

No response shape was broken — `PlayerState`/`CardInstance` decode with `decodeIfPresent` and
explicit `CodingKeys`, so the new fields are ignored. Two endpoints iOS calls were **broken and
are now fixed**, and three behaviours changed:

**Fixed (previously could never succeed from iOS):**
- `POST /api/final/advance` — the route sends `phase`, but `advance_final_phase` only accepted
  `target_phase` → `TypeError`. The Final Tribal could not be advanced from any client.
- `POST /api/final/tie_break` — the route requires `chosenWinner` (which iOS sends) while
  `break_final_tie` only read `winnerId`, so the chosen winner was dropped and the tie-break
  always failed. Both spellings are accepted now.

**Behaviour changes iOS should expect:**
- `POST /api/turn/draw` now **rejects** if the player hasn't stolen this turn, and during a
  tribal council. Message is player-facing.
- `POST /api/vote/cast` now spends real cards: a player must cast **all** their Vote/Goodwill
  Gamble cards, may add Extra Votes, cannot vote for themselves, and must send `votesData: []`
  when they hold no Vote Card. Per-player `voteCards` / `mandatoryVotes` / `maxVotes` are in the
  state to drive that UI.
- `POST /api/tribal/advantage` no longer accepts `advantageType: "extra_vote"` (Extra Vote is
  spent at voting time, not played as an advantage). Valid types: `control_the_vote`,
  `goodwill_gamble`, `im_the_leader_now`, plus the house cards in extended mode.
- `POST /api/player/join` now rejects duplicate names (case-insensitive), duplicate colors and
  malformed colors with a 400.

**Additive:**
- `POST /api/game/create` accepts optional `{deckMode, expansion}` and echoes them back.
- New `POST /api/challenge/action` `{playerId, action, value}` — actions `bid` | `pass` | `pull`
  | `steal` | `dismiss`.
- Game state gains `deckMode`, `expansion`, `necklaceHolder`, `challenge`;
  `currentVote` gains `eliminationsNeeded`, `resolution`, `rawVoteResults`, `finalTribalAfter`;
  players gain `voteCards`, `goodwillVotes`, `mandatoryVotes`, `maxVotes`.
- `POST /api/vote/tiebreak` also accepts `chosenIds: [...]` for a double-elim double pick.
- `reset_tribal_council` now leaves an idle `currentVote` in place instead of deleting the key.

## Hide 'n' Seek — the design question, recorded

Hide 'n' Seek is the one Challenge with no honest digital form. The physical game *is* the
information channel: two Purple Rocks are palmed and bluff-passed hand-to-hand while an Observer
watches for tells — the sound of the rocks, hesitation, a glance. Remove the hands and there is
nothing left to observe, so any digital version has to invent a substitute tell:

1. **Timed decoy animations** — each pass is a short window where the holder chooses to really
   pass or fake it, and the Observer sees only identical animations with real timing jitter. The
   tell becomes reaction latency. Closest to the original but punishes slow connections, which is
   fatal for a phones-around-a-table game.
2. **Bluff statements** — each player publicly claims "passed" or "kept" and the Observer reads
   the claims. Becomes a social-deduction minigame; fun, but a different game wearing the same name.
3. **Physical hybrid** — the app narrates and times the round while players use real hands (or
   any two objects), then the Observer taps their guess. Keeps the real game intact and is by far
   the cheapest to build, but only works when everyone is in the same room.

Shipped as a stub: the card is playable, discards with no effect, and explains why. Option 3 is
the recommendation if it's ever built, since the expansion is a party game played in person
anyway — the app would just be the referee.

## Follow-up findings NOT in the correction plan (left as-is, flagged for Tyler)

Reading the Survival Guide card-by-card turned up four card effects that deviate from the official
text. The review marked all of these ✓ so they were out of scope, and changing card behaviour
without a decision felt wrong — but they are real:

1. **The Spy Shack** — official: *"Look at any player's cards **and take one**."* Ours only looks.
2. **Reward Challenge: Power Pair** — official: pick 2 other players, all 3 show 1–3 fingers; if
   *exactly 2* match they each steal 1 card from the 3rd; if all 3 match everyone discards 1; if
   all differ, play again. Ours simulates random finger counts and only pays out to the player.
3. **Reward Challenge: It's A Numbers Game** — official: everyone shows 1–5 and the **lowest
   unique** number steals 2 random cards from any player, repeating until there's a single winner.
   Ours uses 1–3 and "closest to the player's number".
4. **Reward Challenge: Do Or Die** — official: on a **tie**, each player swaps 1 card of their
   choice. Ours does nothing on a tie.

All four need real multiplayer prompts (simultaneous secret input, like the Rocks challenges now
have) rather than the server rolling dice on players' behalf. The Rocks challenge state machine is
the pattern to copy if you want these fixed properly.

Also worth knowing: **game state ships every player's hand to every client.** The web UI only
renders your own, but the data is there in `/api/game/<id>/state`. Pre-existing, unchanged here,
and not exploitable without devtools — but it is the one remaining place where a determined player
could see more than they should. Fixing it means per-player state filtering on the socket/REST
boundary.

  re-attached them to a socket, and module setup runs at DOMContentLoaded — long before the first
  socket exists. Every server push, `state_update` included, was being dropped; the whole app has
  been running on HTTP polling alone. Fixed by re-attaching stored listeners on socket creation,
  plus: `connect()` on an already-open socket now emits `join` (players pick a game *after* the
  socket is up, so the device was never in the room), `disconnect()` clears `connectionPromise`
  (otherwise the next `connect()` was a silent no-op forever), and a deliberate hang-up no longer
  triggers the reconnect loop or a "connection lost" toast. Live pushes confirmed in Chrome —
  the lobby roster now updates without waiting for a poll.

  Also: the service worker rewrote *every* non-ok API response into a fake 503 "Offline", which
  hid 404s from the app; it now passes real server answers through, and a 404 on a `/game/` route
  clears local state and goes home — so a phone that was asleep during the wipe still recovers.
  And `on_disconnect()` now takes the `reason` python-socketio passes it (it was raising on every
  single disconnect).
