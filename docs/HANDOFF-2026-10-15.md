## Part 2 — How the Mac mini picks it up

### One-time setup on the Mac mini
```bash
cd ~/Documents/GitHub/survivor-game
git fetch origin && git checkout claude/code-review-2026-10-15
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt pytest ruff playwright
.venv/bin/python -m playwright install chromium   # for the UI checklist
brew install xcodegen                              # only if project.yml changes
```

### The loop for each card
1. Take the top `mac-mini` card in **Ready to test** and move it to **Testing**.
2. `git fetch origin && git checkout <branch on the card> && git pull`.
3. Run what the card says. For most cards that is:
   ```bash
   bash deploy/mac-test.sh
   ```
   The script runs:
   - lint;
   - every Python suite;
   - the live API harness and scripted full games against a **scratch** server on port 8097;
   - the Playwright UI checklist;
   - the iOS unit tests (`xcodebuild test -only-testing:SurvivorGameTests`) on the newest iPhone simulator.

   It never touches the live server or `~/srv`.
4. Paste `.test-logs/<timestamp>/summary.txt` as a comment on the card.
   - If everything passes, move the card to **Passed**.
   - If anything fails, move it to **Failed** and attach the failing step's `.log` from the same folder.
5. If a card needs a person (a phone, a real game, a judgment call), comment what you found and move it to **Needs a human**.

### Rules for the Mac mini
- **Never run `deploy/redeploy.sh` from a test card.** Deploying is the D cards below, and only after a human says go. Bouncing the live server drops sockets mid-game.
- **Never touch the live store.** Never point tests at `~/srv/survivor-game` or port 8080.
- **Report outcomes faithfully.** A failing test is reported, not skipped or "fixed" by editing the test.

### Follow-up cards (Backlog)

---
**F1 · Player tokens and hidden hands** — `follow-up` `area:server` `area:web` `area:ios` `P1`

A player is whoever sends their `playerId`, and every phone receives every hand and the in-progress ballots.
- Mint a per-player token at join and require it in `handle()`.
- Send each phone a state with other hands and ballots redacted.

This is the largest remaining fairness and security gap. It needs a coordinated server, web and iOS change.

**F2 · Final Tribal can't stall** — `follow-up` `area:server` `P1`

Jury voting has no deadline, and one absent juror stalls the game's end. `change_leader` doesn't update `finalTribal.leader`. Add a deadline, or let any finalist advance after a timeout.

**F3 · Data directory and nightly backups** — `follow-up` `area:ops` `P2`

Add a `SURVIVOR_DATA_DIR` so runtime state stops living beside the code under `rsync --delete`, plus a nightly backup LaunchAgent.

**F4 · Logs that survive a reboot** — `follow-up` `area:ops` `P2`

Logs go to `/tmp`, which is unrotated and wiped on reboot, and the Socket.IO access log floods the error file. Move logs to `~/Library/Logs/SurvivorGame/` with rotation and turn the access log off by default. Set `HOST=127.0.0.1` in the server plist if nobody plays on the LAN.

**F5 · iOS follow-ups** — `follow-up` `area:ios` `P2`
- Refresh the card catalog from `/api/cards`.
- Resync on `scenePhase` → active.
- Dynamic Type for `Torch.Font.body` and `.label`.
- Play cards by uid, not index.
- Add re-entrancy guards on view-model actions.
- Regenerate the stale fixtures and add Final Tribal ones.

**F6 · Bots use their advantages** — `follow-up` `area:bots` `P2`

Bots never play Control The Vote, I'm The Leader Now, Steal A Vote or Block A Vote, and never cast Extra Votes.

**F7 · Stale e2e tests** — `follow-up` `area:web` `P2`

Several pytest-playwright e2e tests click start-screen buttons that no longer exist ("Create New Game", "Join Existing Game"); some also expect old card counts. Update or retire them. The stale clicks are in `tests/e2e/conftest.py`, `test_01_smoke.py`, `test_02_lobby.py`, `test_09_mobile_security.py` and `test_11_full_ui_flow.py`. These tests aren't part of `deploy/mac-test.sh`; the live API and scripted-game harnesses that it does run are current.

**F8 · Dependencies** — `follow-up` `area:ops` `P2`

Split `requirements.txt` into server, bot and dev; add a lockfile; consider dropping the unmaintained `gevent-websocket`, since websockets work without it on Flask 3.1.
